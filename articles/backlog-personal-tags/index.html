Backlogを変更せず、自分用のタグや優先順位を付ける方法

チームの優先度は同じでも、自分が着手する順番は違うことがあります。別プロジェクトの課題をまとめて確認したいときも、チーム全員の分類を変える必要はありません。個人用の整理を重ねる考え方を紹介します。

01 / GUIDE

共有情報と個人の判断を分ける

Backlogのステータスや優先度は、チームで状況を共有する情報です。自分が読み返したいから優先度を上げたり、返信待ちの意味で独自のステータスへ変更したりすると、他の人が意図を読み取りにくくなることがあります。

個人の整理では「いつ取り組むか」「何と関連するか」「どれから見るか」を分けます。共有情報を維持しながら、この3つの判断を別に持つと、チームと個人の両方で使いやすくなります。

02 / GUIDE

タグは横断して探すための印にする

タグは、複数の課題を同じ観点でまとめる用途に向きます。例えば「今週リリース」「レビュー」「見積もり」などです。顧客やプロジェクトを越えて同じ種類の仕事を確認できます。

  • 「今週リリース」：公開前にまとめて確認する課題。
  • 「レビュー」：まとまった時間に確認したい課題。
  • 「見積もり」：作業規模や回答内容を検討する課題。

「急ぎ」「重要」「最優先」を全部作ると意味が重なります。タグ名だけで用途が分かる少数の分類から始め、使わなくなったものは定期的に整理しましょう。

03 / GUIDE

優先順位は着手順として決める

期限、他の人の作業を止めているか、今着手できるかを確認して並べます。チーム上は優先度が高くても、必要な素材が揃っていないなら、自分の次の作業は別の課題かもしれません。

例として、明日締切のレビューは他の人の修正時間を確保するため先に行い、今日中の単独作業を次にする、といった判断があります。期限そのものを変えるのではなく、自分の並び順で表します。

04 / GUIDE

タグ・今日・待ちを組み合わせる

「レビュー」は作業の種類、「今日」は実施する予定、「待ち」は次の行動に条件がある状態です。同じ課題にそれぞれ異なる意味を持たせると、タグにすべてを詰め込まずに済みます。

個人の整理を終えただけでは、チームへの報告は完了しません。レビュー結果や期限変更の合意など、他の人が必要な情報は元のBacklog課題へ残します。日々の選び方は今日やることを個人管理する方法でも紹介しています。

05 / GUIDE

IssueDockで自分用の整理を重ねる

IssueDockでは個人タグ、個人ステータス、今日、ピン、ドラッグによる並び順を使って課題を整理できます。これらはIssueDock内の個人整理情報で、Backlog側の課題を変更しません。

同じGoogleアカウントでChrome同期を利用している場合、個人整理データを端末間で同期できます。チームへ共有するタグとは異なるため、共同作業に必要な分類はBacklog側の運用と使い分けてください。
